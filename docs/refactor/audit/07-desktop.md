# Audit 07: crates/desktop (read-only; ~23.6k lines incl. golden txt)
Evidence is from grep/sed reads at HEAD 214a664; I did not read every line. Items marked (unverified) need a closer look.
Android path prefix below: `K/` = android/app/src/main/kotlin/com/osvauld/p2p.

## 0. Top findings (ranked payoff/risk)
1. **Logic that exists twice (Rust desktop + Kotlin) and has already drifted.** The proof is the call-quality bars: desktop `view.rs:~158` uses <100ms/<200/<350, Android `K/Support.kt:77` uses <120/<250/<450. Same for end-reason wording, link-failure wording, initials, ago/clock formatting, group system lines, host conditions, emoji rules. Section A has the Rust API proposals. Payoff is high and risk is low (pure functions, UniFFI already exists in `crates/core`, Android already imports `uniffi.p2pcore`).
2. **The groups preview stack (groups.rs 327 + groups_fake.rs 1761 + groups_view.rs 1157 = ~3.2k lines)** is placeholder UI for features the core now has (`group_live*` is real). Preview is reachable in debug/test-hooks builds only (`groups.rs:12 PREVIEW_DEFAULT`). Android has the same pair (`K/FakeGroupsPrivacy.kt` 510 lines). Delete or reduce after the UI port. Only the screens with no live equivalent still need it (hosting page `view.rs:1588`, privacy/address-change, 1:1 blocked states). Saves ~2.5-3k lines.
3. **`App::update_inner` is ~1000 lines (app.rs:1108-2108) in a 2271-line file; `view.rs` is 1992 lines.** Natural seams exist (section D). Pure mechanical split; saves 0 lines but is the main readability win.
4. **Theme tokens/style helpers are decent in ui.rs, but spacing/radius/font-size literals are scattered** (hundreds of `.spacing(..)`, `padding([..])`, `size(13.0)`). A small `ui::sp`/`ui::r`/`ui::ty` token set and 5-6 shared row/card/header builders would remove ~600-900 lines of repeated layout code (section B).
5. **`group_live_tests.rs` `Fake` (935-line file) re-implements the core's group rules** (owner/admin/3 flags/removed/host) on `RefCell`s. It tests the desktop against a model of the core, not the core. Better: a core-provided in-memory `GroupApi` (or the `group-sim` crate) used by desktop, Android and tests.

## A. Logic that should move to shared Rust (priority section)
Pattern: put pure presentation-agnostic logic in a new `crates/core/src/present/` (or new crate `tin-present`, no iced/cpal deps) and export through the existing UniFFI surface. Desktop calls it directly. Android replaces its Kotlin copy with the generated binding. UI layers keep only widgets. "Dup?" = Android re-implements (grep-confirmed).

## B. Duplicated UI code (desktop)
Positives: `ui.rs` already has tokens (`Tok`, `LIGHT/DARK`, `ui.rs:70-134`), `button_style`, `row_style`, `input_style`, `card`, `plain`, `pop_surface`, `sheet_surface`, `raised`, `outlined`. Gaps:
- **Layout literals:** `.spacing(`/`padding(`/`Length::Fixed` appear 121x view.rs, 85x group_live_view.rs, 69x groups_view.rs, 42x chat_view.rs, 27x link_view.rs. No spacing/radius/type-scale tokens, so `size(13.0)`, `padding([5, 12])`, radius 999.0 pill (`view.rs:~139`, `container(r).padding([5, 12]).style(ui::plain(bg, 999.0))`) are repeated. Propose `ui::sp::{XS,S,M,L}`, `ui::radius::{CARD,PILL,...}`, `ui::ty::{caption,body,title}` returning `Text`. Save ~300 lines, high consistency gain, low risk.
- **Helper functions defined per view file instead of in ui:** `groups_view.rs:~91 sys()`, `groups_view.rs:~60 rule()`, `and_list`, `when/day/hhmm` (`groups_view.rs:27-38`) are imported by group_live_view (`use ... when`). They are generic widgets/format helpers living in the *preview* file, so deleting the preview (finding 2) would break the live view unless moved first. Move to `ui.rs`/`present`.
- **Parallel screen pairs:** `groups_view.rs` vs `group_live_view.rs` (same dialogs: new/join/invite/flag/removal/hosting, member actions, members pane, lines `groups_view.rs:469,503,1008-1019` vs `group_live_view.rs:529-534`). Both already carry the "N of 3 flags" text and the "flag N of M" paragraph. After deletion of the preview, nothing to dedupe; until then share via ui helpers.
- **Pill/badge/chip, avatar row, section header, settings row:** repeated across `view.rs` (settings_view 1363-1605 is a 240-line function), `chat_view.rs`, `link_view.rs`. Propose `ui::components::{pill, badge, section_title, settings_row(label, control), person_row(avatar,name,sub,trailing), dialog(title, body, actions)}`; est. -400 lines.
- **Dialog scaffolding:** every dialog (`groups_view`, `group_live_view`, `link_view`, `view.rs` offer/exists/avail panels) builds its own `container(column).style(sheet_surface/pop_surface)` + button row; one `ui::dialog()` would cover ~10 dialogs.
- **Onboarding/unlock family** `view.rs:251-543` (onboarding, exists_panel, name_device, key_failed, key_lost, unlock, setpass, phrase) all call `self.shell(...)` + `pass_field` + `wide`; already partly shared. Moving them to `view/onboarding.rs` is a pure move.

## C. Duplicated state/update logic
- **Notice/error handling:** `self.notice = Some(..)/None` set ~40 times in `link.rs` alone (`link.rs:110,124,155,166,201,210,222,...`), plus `groups.rs:83,185`, `group_live.rs` `gerr`. Propose `App::say(&mut self, impl Into<String>)` / `App::clear_notice()` and a `Result<T,Error>` extension `.or_notice(self)` using the (core-owned) friendly error text (`friendly()` in link.rs ~222 is the only core Error to words mapper; belongs in core: `Error::user_text()`, used by both apps and replacing `group_live.rs:150 gerr`). Saves ~80 lines and makes Android consistent.
- **Async tasks:** only ~10 `Task::perform`/`spawn_blocking` sites (app.rs 5, chat.rs 1, shell_search.rs 2), so core calls are mostly synchronous on the UI thread (`GroupApi` calls in `Job::run(api)` and `Blocks::refresh` are blocking). Risk: UI hitches if Node calls take locks. A single `fn off_thread<T>(f: impl FnOnce(&Node)->T + Send, then: fn(T)->Msg) -> Task<Msg>` wrapper would standardise it.
- **Core event funnelling:** `main.rs:197` `on_status`, `Ev` enum (`main.rs:~48`) plus `EvBox` (`app.rs:438`) plus `App::on_event` (`app.rs:2108`) plus separate `ChatEvents`/`GroupCallEvents` bridges (`chat.rs`): unify into one `Ev` bridge; Android has the same per-listener split (`GroupsController : GroupEvents, GroupRequestEvents, GroupInvitationEvents`, `K/GroupsCore.kt:303`). A core-level single `events() -> Stream<CoreEvent>` (or one callback interface) would let both UIs drop their adapters.
- **Trait-wrapped core with stand-ins:** three parallel patterns: `BlockApi` (`blocks.rs:21`), `GroupApi` (`group_live.rs:31`, 30 methods plus a delegating impl for `Node` at 65-148 that is ~85 lines of boilerplate), `chat::Source` (`chat.rs`, with `chat_fake.rs`). Kotlin has the same (`K/GroupsCore.kt:39 GroupApi` plus `NodeGroupApi:77`, `K/ChatSource.kt`, `K/GroupsSource.kt`). If core exported the traits (UniFFI `Node` already is the real impl), both clients could drop the delegating impls. A macro or `impl<T: Deref<Target=Node>>` would cut ~85 lines from group_live.rs immediately.

## D. groups_fake.rs vs group_live.rs
- `groups_fake.rs` is **still compiled** (`main.rs:28 mod groups_fake`, not test-hooks gated) and used by `groups.rs:9` (preview state) and `groups_view.rs`; also `demo.rs:286-314` (design screenshots) and `view.rs:1588` (hosting page only `if self.demo && self.groups.on`). Settings switch default is debug/test-hooks (`groups.rs:12`). So in release builds it's dead weight at runtime but compiled in.
- Overlap with live: roles, flags (`FLAGS_TO_REMOVE=3` defined in groups_fake.rs:24, group_live.rs and Kotlin), members, hosts, chat requests, invitations. Different shape (fake `Snap`/`Group`/`Member` vs core `GroupSummary`/`GroupDetail`): no shared trait, and none should be introduced: the fake predates the core API. Recommended: (1) keep only what has no live equivalent: Person/Perms/Block/AddressStatus/Interval (blocking, address-change, 1:1 states). Check whether `blocks.rs` now covers blocking so those can go. (2) Gate the remaining module behind `cfg(any(debug_assertions, feature="test-hooks"))` at `main.rs:28` right now (cheap, zero risk), then delete when the port lands. Do not touch the design references (UI port in progress).
- Dead markers in groups_fake: `allow(dead_code)` at lines 120,166,181,262,267,271 ("core API shape; the screens don't need it yet") = ~100+ unused lines.
- `Fake` in `group_live_tests.rs:33-135` is a *second* fake of the same group rules (see top finding 5).
