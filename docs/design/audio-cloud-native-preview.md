## Same field, native drawing

Reference: design-refinement's `calls/field/{model.ts,gl.ts,CloudField.svelte}`.
The Rust numerical model ports the five Gaussian masses, aspect-normalised
Lissajous coefficients, OKLab conversions/mixing, light teal/gold and dark
teal/amber palettes, state targets and their easing overrides. Fog domain warp
and lit Worley/fBm clouds are translated from GLSL to WGSL, using **Iced's existing
wgpu Shader widget**. No added dependency, Vello, or new rendering engine.

The 1:1 identity stage and group roster reuse that same field. Names, speaking
labels, status, timer, host line and controls have fixed-height slots; timer uses
existing IBM Plex Mono. Avatars/controls do not move with audio. Main exit control
is on the centre axis. Candidate D mark is a static mono snapshot generated by
the playground's `markPaths({})`, not an independently hand-drawn replacement.

Speech input is experimental: measured low/mid/high balance changes individual
mass swell/coverage and palette, bounded by smoothed energy. Spectral balance is
**not pitch**. Shared `fixture::tone_pcm` feeds both native experiments. Simulated
phrase/overlap gates are design fixtures, not authenticated receiver playout.
No production descriptor API or exact recovered/faded PCM lineage is asserted.

## Deliberate differences / unfinished work

- Cue-bus patterns/audio and live brand choreography are **not wired**. State
  buttons are silent; do not claim complete sound/motion parity.
- Reduced motion freezes existing centres, radii, warp and texture time, avoiding
  the playground's snap to its separate tau=7.3 static preset. Colour/opacity may
  respond; geometry envelopes pause and resume continuously. This preserves the
  user's earlier no-snap requirement. It needs joint accessibility review.
- Three text/host/control calm patches are supported, rather than truncating the
  third group patch as the browser renderer currently does. Same dark strength
  0.45, light 0, dark chroma gain 1.55.
- Texture is faded to the exact background on end/failure as well as lobe alpha;
  otherwise the clouds' baseline puffs can remain visible at zero coverage.
  End/failure stop subscriptions when fade completes.
- This is native screen-context composition, not a pixel-identical port of every
  playground layout/transition, and is not production UI integration.
- Shader currently draws at native widget resolution, without the browser's
  700k pixel/0.7 cloud scale cap. Review native draw cost and a bounded-resolution
  adapter before production/mobile; **no GPU frame-time/battery claim**.

## User feedback revision: icons and weak microphone response

User reported poor icons and little microphone influence. Replaced raster call
icons with native Canvas paths, parsed once using the existing usvg dependency
from the playground's exact mic/micoff/phone/vol SVGs. No new dependency. Controls
now centre a 28px vector glyph inside a 64px button with zero padding. End uses
phone rotated 135 degrees, not a crossed-out phone. Speaker uses the volume glyph,
not a telephone; selected mute/speaker controls use inverted colours.

Test-first regression at a representative 0.35 input: the old radius increase was
0.01188577 short-side units (~4.6%). New test requires at least 0.035 radius change,
0.20 alpha change and 0.015 texture-warp change within 20 frames. It failed before
the mapping change and passes afterwards. These are model thresholds, not measured
human microphone levels or a perceptual/GPU guarantee.

Speech now has 45ms energy attack / 320ms release, 70ms geometry response,
spectral redistribution of persistent masses (offset <=0.06375 short-side units),
stronger bounded radius/coverage and texture warp. Radius <=0.49, alpha <=2,
existing composite cap unchanged. Reduced motion continues to freeze centres,
radii, warp and texture phase while colour/opacity respond; all previous parity,
no-snap and lifecycle tests still pass.

Added explicit preview **Mic sensitivity**, default 1.6x, range 0.5–3x, and live
**visual drive %** next to the raw -dBov level. Gain only maps the visual descriptor;
it does not modify captured PCM, transmission, or bypass the adapter's experimental
RMS>200 audibility gate. Zero/inaudible input remains zero at any sensitivity.
Physical microphone behaviour still needs user feedback; no capture started by us.
